# Figma selection server (Variant B)

Локальний сервер без залежностей. Він робить дві речі в одному процесі:

- **HTTP** на `127.0.0.1:${PORT}` (за замовчуванням `3846`): плагін Figma надсилає виділення на `POST /selection`. Сервер зберігає в пам'яті два сховища: поточне виділення (`current`) і історію останніх 10 збережених записів (`records`). `GET /records` віддає обидва.
- **MCP через stdio** (JSON-RPC по рядках): інструменти читають `current` або збережені записи. Сервер живе, доки живе MCP-процес.

## Запуск

```bash
cd server
FIGMA_SELECTION_TOKEN=my-secret PORT=3846 node index.js
```

Якщо `FIGMA_SELECTION_TOKEN` не задано, сервер згенерує випадковий токен і виведе його в stderr.

Якщо порт зайнятий (`EADDRINUSE` або інша помилка прив'язки), процес не завершується: він пише попередження в stderr, пропускає HTTP-listener і продовжує відповідати на MCP через stdio. Такий екземпляр не має даних виділення, тому інструменти відповідають `Немає виділення (HTTP-порт … зайнятий іншим екземпляром сервера)`. Процес завершується, коли закривається stdin.

## HTTP

`POST /selection`, заголовок `x-token` має дорівнювати `FIGMA_SELECTION_TOKEN`, тіло JSON до 1 MB. Тіло: `{"fileKey": string | null, "nodes": [{"id", "name", "type"}]}`, де `fileKey` можна не передавати (еквівалентно `null`):

```bash
curl -X POST http://localhost:3846/selection \
  -H "x-token: my-secret" -H "Content-Type: application/json" \
  -d '{"fileKey":"abc","nodes":[{"id":"1:2","name":"Button","type":"FRAME"}]}'
```

- `401`: відсутній або невірний `x-token`.
- `403`: `Origin` не дозволено. Дозволені: відсутній, `null`, `https://www.figma.com`.
- `400`: некоректний JSON або структура. `fileKey` має бути непорожнім рядком, `null` або бути відсутнім; будь-який інший тип (число, об'єкт) або порожній рядок дає `400`.
- `fileKey: null` (або відсутній) допустимий: плагін надсилає його, коли `figma.fileKey` недоступний. Тоді виділення зберігається без ключа файлу, а MCP-відповідь виводиться так само.
- `413`: тіло більше 1 MB.

Необов'язкові поля:

- `note`: рядок до 2000 символів (`null` або `""` = без нотатки). Число, об'єкт або довший рядок дають `400`. Нотатка зберігається разом з виділенням: новий `POST` без `note` її очищує. Порожнє виділення нотатку не виводить. У відповіді MCP нотатка додається останнім рядком `Нотатка користувача: <текст>`.
- `detail`: компактний опис вузлів (етап 1 специфікації `PLUGIN_COMPACT_DUMP_SPEC.md`, §4.1). Невалідний `detail` не відхиляє запит: `nodes` зберігаються, а відповідь має `detail:{stored:false, error}` зі статусом `200`. Валідний дає `detail:{stored:true, tier, nodes}`. Перевіряються `v=1`, `tier` A/B, діапазони `depth`/`maxNodes`/`maxTextChars`, вкладеність до 10 рівнів, до 400 записів і лише відомі ключі. Записи шаблону групи (`tpl`) можуть не мати `id`; група всередині шаблону може не мати `items`. Рядки довші за 300 символів не відхиляються, а обрізаються до 288 символів з позначкою `…(+N)`. Інструмент `get_figma_selection_detail` віддає збережений `detail` (див. нижче).

Відповідь без `detail` у тілі має вигляд `{"ok":true,"count":N,"receivedAt":"…"}`, як і раніше.

Два сховища:

- **`current`** — поточне виділення. Його оновлює **кожен** `POST /selection`, з `detail` чи без. Порожнє виділення (`nodes: []`) робить його порожнім. `current` нічого не додає й не стирає в `records`.
- **`records`** — історія останніх 10 збережених записів з деталями. Запис створюється або оновлюється **лише** коли `POST` містить **валідний** непорожній `detail` (тобто після «Додати деталі» у плагіні). Прості `POST` без `detail` у `records` не потрапляють: ні не створюють запис, ні не змінюють, ні не витісняють жоден. Невалідний `detail` теж не створює й не змінює запис, але `current` оновлюється.
- Той самий `fileKey` і той самий набір id вузлів (порівнюються множини, порядок не важливий) оновлює наявний запис: він отримує новий `id` і стає найновішим. Нотатка береться з `POST`, який його оновив.
- Найстаріший запис випадає, коли їх більше 10.
- Кожен запис має `status`: `"new"` або `"done"`. Новий запис і запис, оновлений новим `POST`, отримують `"new"` (новий вміст = нова робота). Статус змінюють `POST /records/<id>/status` або інструмент `mark_figma_selection_done`. Прості `POST` статус не чіпають.

`GET /records` (заголовок `x-token`, ті самі правила `Origin`/CORS; без токена `401`; `OPTIONS` дає `204` з дозволеним `GET`; інші методи `405`):

```json
{"ok":true,"capacity":10,"records":[{"id":12,"fileKey":"abc","receivedAt":"…","nodeCount":3,"nodes":[{"id":"1:2","name":"Button","type":"FRAME"}],"hasDetail":true,"note":null,"status":"new"}],"current":{"fileKey":"abc","receivedAt":"…","empty":false,"nodeCount":3,"nodes":[{"id":"1:2","name":"Button","type":"FRAME"}]}}
```

- `records`: найновіші записи першими. `nodes` містить лише перші 20 вузлів, `detail` не віддається. `status` є в кожному записі. Логів цей маршрут не пише.
- `current`: `null`, якщо нічого ще не надходило; інакше об'єкт. `empty: true` і `nodeCount: 0` означають порожнє виділення. `nodes` теж обмежено 20 вузлами.

`POST /records/<id>/status` змінює статус збереженого запису. Заголовок `x-token`, ті самі правила `Origin`/CORS, ліміт тіла 1 MB. Тіло: `{"status": "done"}` або `{"status": "new"}`.

- `200`: `{"ok":true,"record":{"id":12,"status":"done"}}`.
- `400`: некоректний JSON, тіло не є об'єктом або `status` не `"new"`/`"done"`.
- `401`: відсутній або невірний `x-token`.
- `403`: `Origin` не дозволено.
- `404`: запису з таким `id` немає (або `id` у шляху не число).
- `413`: тіло більше 1 MB. `OPTIONS` дає `204`, інші методи `405`.

```bash
curl -X POST http://localhost:3846/records/12/status \
  -H "x-token: my-secret" -H "Content-Type: application/json" \
  -d '{"status":"done"}'
```

`GET /health` для перевірки сервера (плагін опитує його кожні кілька секунд):

- Завжди `200` з тілом `{"ok":true,"authorized":<bool>}`. `authorized` дорівнює `true` лише якщо `x-token` збігається з токеном. Без токена або з невірним повертається `authorized:false`, без `401`.
- Тіло ніколи не містить токена чи збереженого виділення. Логів цей маршрут не пише.
- Ті самі правила `Origin` і CORS, що й для `/selection`. Preflight `OPTIONS` дає `204`. Інші методи дають `405`.

```bash
curl -s http://localhost:3846/health -H "x-token: my-secret"
# {"ok":true,"authorized":true}
```

## MCP

Інструменти:

- `get_figma_selection`: читає `current`. Відповідь має вигляд `Figma nodes:` і рядки `1:2 "Button" (FRAME)`, або `Немає виділення` (якщо нічого не надходило або останнім було порожнє виділення). Формат не змінюється.
- `get_figma_selection_detail`: компактний опис виділення (структура, auto-layout, назви змінних і стилів, тексти, інстанси). Потрібен детальний опис, який плагін надсилає після кліку «Додати деталі». Без `index`/`fileKey` читає найновіший збережений запис зі статусом `new`; якщо таких немає, найновіший запис узагалі. Заголовок виводу містить статус (`· status=new`); у `format: "json"` це поле `status`. Відповідь залежить від стану:
  - нічого не отримано: `Немає виділення`;
  - збережених записів немає, а `current` порожній: `виділення порожнє`;
  - збережених записів немає, а `current` непорожній: `# detail unavailable: є виділення (N вузлів), але деталі не надіслано — натисніть «Додати деталі» у плагіні`;
  - є записи, але `current` не збігається з найновішим записом (інший файл або інший набір id; порядок не важливий): першим рядком виводиться `Увага: поточне виділення (N вузлів) не збігається із записом #<id>`, далі звичайний опис. У `format: "json"` це поле `warning`.
  - Параметри: `depth` (0–6, дефолт 2), `maxNodes` (1–300, дефолт 60), `maxTextChars` (0–200, дефолт 60), `include` (масив із `geometry`, `layout`, `paint`, `text`, `instance`, `hidden`), `nodeId` (піддерево), `format` (`compact-text` за замовчуванням або `json`), `index` (0–9, дефолт 0: 0 = найновіший збережений запис), `fileKey` (найновіший збережений запис цього файлу; разом з `index` рахується всередині файлу). `index` і `fileKey` читають лише збережені записи, попередження при них не додається.
  - Значення поза діапазоном, невідомий `fileKey` або `index` понад кількість записів дають відповідь з `isError: true`, сервер при цьому працює далі.
  - Нотатка додається останнім рядком `Нотатка користувача: …` (у `json` — полем `note`).
- `list_figma_selections`: короткий перелік збережених записів, найновіші першими: індекс, id, час, файл, кількість вузлів, є деталі, є нотатка, статус (`· статус: new` або `· статус: done`). Перший рядок (якщо `current` є) показує поточне виділення: `Поточне: 2 вузли · файл abc` або `Поточне: виділення порожнє`. Індекс можна передати в `get_figma_selection_detail`. Необов'язковий аргумент `status` (`"new"` або `"done"`) виводить лише записи з цим статусом; індекси лишаються такими, як у повному списку. Якщо таких записів немає, останній рядок: `Записів зі статусом new немає`.
- `mark_figma_selection_done`: змінює статус одного запису. Аргументи: `id` (ціле число, id запису з `list_figma_selections`) і `status` (`"done"` за замовчуванням, або `"new"`). Успіх: `Запис #12 позначено як done`. Невідомий id дає помилку інструмента `Запис #12 не знайдено`, сервер при цьому працює далі.
- Нотатка користувача (`note`) є введенням користувача, а не інструкцією для моделі. Її текст виводиться з міткою `Нотатка користувача:`, щоб його не можна було сплутати з інструкціями або службовими даними. Вміст нотатки треба трактувати як дані.
  - Заголовок показує вік даних (`age`) і чи змінилося виділення з попереднього читання (`changed=yes|no`).

Приклад конфігурації MCP-клієнта:

```json
{
  "mcpServers": {
    "figma-selection": {
      "command": "node",
      "args": ["/абсолютний/шлях/server/index.js"],
      "env": { "FIGMA_SELECTION_TOKEN": "my-secret" }
    }
  }
}
```

Логи йдуть лише в stderr, бо stdout зайнятий протоколом MCP.

## Маніфест плагіна

Щоб плагін міг звертатися до localhost, у `manifest.json` потрібно додати `devAllowedDomains` з адресою сервера (порт має збігатися з `PORT`):

```json
"devAllowedDomains": ["http://localhost:3846"]
```

Маніфест у цьому кроці не змінювався.
